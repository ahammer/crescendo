## Change in this PR

**Preserve other workers' drafts when retiring an issue.** At October 4 02:12:35 UTC,
[PR #1111](https://github.com/ahammer/metalrain/pull/1111) received the automatic comment that
issue #1115 had retired and closed. Its worker explicitly reopened it at 02:37:57 UTC because it
belonged to #1110; the final 03:16:17 closure was a separate independent-delivery rejection.
Current source's retirement matcher accepts any `#N` or `issue-N` mention in a draft body.
That conflates ownership with a reference to a required baseline failure. The broad matcher is
a reproducible causal explanation consistent with the recorded wrong-owner closure; the original
body at cleanup was not retained, so its exact triggering text remains unknown. [G, inspected source]

The change limits GitHub draft cleanup to explicit ownership: a body line starting with a closing
keyword plus the exact local issue number, a `Symphony issue: #N`/`Crescendo issue: #N` line,
or an `issue-N` branch segment with an optional hyphenated suffix. Incidental dependencies,
other numeric prefixes and non-draft PRs remain open. Actual retired-item draft cleanup continues;
no scheduler, route, service endpoint or local configuration is added.

The existing API-boundary regression now includes the observed ownership/dependency shape,
incidental prose and branch-like body text, number-prefix collisions, closing keyword forms,
both ownership footers and actual issue branches. On original main it fails because retirement
closes the other owner's draft. After the fix it must close only explicitly owned drafts.
`SPEC.md`, `elixir/README.md` and `docs/crescendo.md` describe the same contract.

The regression fails on original main with the unintended PATCH closing the other owner's
draft. After the fix, all **18 GitHub adapter tests pass**. The required
`cd elixir && mise exec -- make all` passed under the machine lease: format, public specs,
strict Credo, **557 tests with zero failures and six live-test skips**, **100% coverage** for
non-ignored modules, and Dialyzer with zero errors. PR-description validation and
`git diff --check` also pass. A final inventory check reconciles every cycle merge, final
unmerged closure, new issue and observed worker scope; the report contains no host paths or
credentials.
